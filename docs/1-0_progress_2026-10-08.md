## 실측 (모델 동봉 한국어 wav 4개, 2.7~6.6초, CPU 4스레드)

| 구성 | 모델 | CER | 첫 Partial p50 | flush / 재인식 p50 | RSS |
|---|---|---|---|---|---|
| A0 스트리밍 | Nemotron 3.5 560ms int8 | 0.00% | 929ms | flush 218ms | +722MB |
| A0 스트리밍 | Nemotron 3.5 160ms int8 | — | 0.6~1.1초 | **실시간 불가 (RTF 1.2~1.3)** | — |
| 대조군 | zipformer-ko 2024-06-16 | 11.84% | 554ms | flush 41ms | — |
| B 2차 | Qwen3-ASR 0.6B int8 | 0.00% | — | 1373ms (hotwords 시 2371ms) | +1013MB |

- 동봉 wav는 깨끗한 낭독 음성이라 CER 0%는 상한선이다. 본인 목소리·개발 용어 230문장으로 다시 재야 한다.
- Nemotron 560ms의 첫 Partial 929ms = 청크 560ms + 디코딩. 1-1 게이트(300ms)는 집 PC GPU에서 160ms 청크로 잰다.
- Qwen3-ASR 0.6B: CPU RTF 0.3~0.4. 10초 발화면 3~4초. 2차 재인식 지연 게이트(300ms)는 집 PC GPU 전용.
- 한국어가 아닌 음성에 `language=Korean`을 강제하면 환각 반복이 생긴다(19초). 한영 혼용 평가 때 언어 강제/auto를 둘 다 측정한다.

## 발견한 제약

1. **Qwen3-ASR 1.7B int8은 GitHub 릴리스에 없다.** modelscope `zengshuishui/Qwen3-ASR-onnx/model_1.7B`(약 2.4GB)에서 수동으로 받아 `models/qwen3-asr-1.7b-int8/`에 둔다. 지금 config 기본값은 0.6B.
2. **Nemotron hotword는 sherpa-onnx 1.13.8에서 프로세스 강제 종료**를 일으킨다(Python 예외 아님). 어댑터가 하위 프로세스로 먼저 확인하고 greedy로 폴백한다. PR #3895 포함 릴리스가 나오면 자동으로 켜진다.
3. **sherpa-onnx에 Cohere Transcribe 오프라인 모델도 있다** (`sherpa-onnx-cohere-transcribe-14-lang-int8-2026-04-01`, 1.7GB, `OfflineRecognizer.from_cohere_transcribe`). 구성 C도 단일 런타임으로 가능. 어댑터는 아직 없음.
4. **이 PC의 기본 마이크 2개가 완전 무음(RMS 0)**으로 잡힌다. Windows 설정 > 개인정보 > 마이크 접근 허용과 음소거를 확인해야 본 녹음이 가능하다. "스테레오 믹스" 장치만 신호가 있었다.
5. Nemotron 160ms는 이 CPU에서 실시간이 안 된다. config 기본값을 560ms로 바꿨다.
